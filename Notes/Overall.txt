1. MODERN JAVASCRIPT (ES6+) ESSENTIALS
-------------------------------------------------------------------------------

  - .filter(): Removes items based on conditions.
  - .reduce(): Accumulates data values.

    console.error(error);
  }

5. HOOKS REFRESHER & COMPONENT STATE MANAGEMENT: USEEFFECT USESTATE
-------------------------------------------------------------------------------
* useState(): Declares a reactive variable container.
  - Syntax: const [stateName, setStateName] = useState(initialValue);
  - Rule: Never modify 'stateName' directly. Always pass the new value to 
    'setStateName()', which tells React to instantly rebuild the screen layout.

* useEffect(): Synchronizes your component layout with external systems (APIs).
  - Syntax: useEffect(() => { ... }, [dependencies]);
  - Rule: If dependencies array is empty '[]', the internal code executes 
    exactly once when the page finishes its initial browser paint step.

6. ARRAY MAPPING SYNTAX (.MAP) IN JSX: CONVERTING OBJECTS TO UI ELEMENTS
-------------------------------------------------------------------------------
The '.map()' method loops through an array of objects and converts each raw data 
entry into live visual layout code blocks.

* Syntax Architecture:
  {arrayVariable.map((singleItem) => (
     <Element key={singleItem.uniqueId}>{singleItem.property}</Element>
  ))}

* Critical Execution Rules:
  1. Implicit Return: Use parentheses '()' after the arrow '=>' instead of curly 
     brackets '{}'. This forces JavaScript to return the visual layout elements.
  2. The 'key' Prop: You MUST pass a unique identifier (like 'key={blog.id}') to the 
     outermost wrapper element inside the loop. This allows the Virtual DOM to 
     instantly identify, update, or remove that specific element without 
     rerendering the whole list when changes happen.
  3. Short-Circuit Safety: Notice 'Array.isArray(blog.tags) && blog.tags.map(...)'. 
     Using '&&' ensures the code confirms the target variable is an actual array 
     before running mapping functions, preventing app crashes if a field is empty.

7. TEMPLATE LITERALS (STRING INTERPOLATION WITH ` AND ${}) : STRING LITERALS
-------------------------------------------------------------------------------
Instead of messy string concatenations using the plus sign ('/Problems/' + id), 
modern JS uses backticks (``) to form string dynamic evaluations.

* Syntax Rules:
  - Enclose the entire string block in backticks: `your string text here`
  - Wrap any JavaScript variables or logical checks inside: ${variableName}

* Real-World Use Case (Dynamic Navigation Routing Links):
  <Link to={`/contests/${contest.id}`}>
  
* Advanced Evaluative Logic Inline:
  `${days > 0 ? `${days}d ` : ""}` // Resolves a ternary string check inside a string!

8. JAVASCRIPT FUNCTION DEFINITION VARIATIONS : JAVASCRIPT FUNCTIONS
-------------------------------------------------------------------------------
Your friend mixes functional syntax forms throughout this codebase. Here is how 
to tell them apart and why they are used:

* Style A: Arrow Functions (Assigned to Constants)
  - Syntax: const getContestStatus = (contest) => { ... };
  - Use Case: Helper calculations outside components. They don't have their 
    own internal contextual tracking scopes ('this'), making them fast.

* Style B: Traditional Component Function Declarations
  - Syntax: function Contests() { ... }
  - Use Case: Declaring structural React components. Hoisted by the JS compiler, 
    making it readable and clear to locate core module boundaries.

* Style C: Inline Anonymous Arrow Functions
  - Syntax: {contests.map((contest, index) => { ... })}
  - Use Case: Thrown inside looping arrays or click triggers ('onClick={() => call()}') 
    where you only need a function to exist for one line of immediate code execution.

11. BROWSER DATA CACHING (LOCALSTORAGE ENGINE)
-------------------------------------------------------------------------------
LocalStorage saves raw data directly inside the user's internet browser cache. 
The data persists permanently unless manually wiped or cleared by code logic.

* Core Command Rules:
  1. Save Data    : localStorage.setItem('keyName', 'string_value');
  2. Retrieve Data: localStorage.getItem('keyName');
  3. Delete Data  : localStorage.removeItem('keyName');

* JSON Parsing Restriction: LocalStorage can ONLY store raw text strings. To pass 
  complex objects or data arrays through cache storage, use conversions:
  - Object to String : JSON.stringify(userObject)
  - String to Object : JSON.parse(textString)

14. OPTIONAL CHAINING INTERPRETATION (THE '?.' OPERATOR)
-------------------------------------------------------------------------------
Avoid system crashes caused by attempts to read property values nested deep 
within undefined or incomplete data structures.

* The Syntax Rule:
  if (!user?.id) { ... }  // Safely evaluates if user is populated first

* How it executes:
  1. Without Chaining: If 'user' equals null, user.id instantly throws a critical 
     uncaught exception error that completely crashes your application screen.
  2. With Chaining: If 'user' is null, the evaluation stops immediately, yields 
     'undefined' safely, and avoids throwing an active JavaScript runtime error.

15. THE 'FINALLY' ENGINE IN BLOCK TRANSACTIONS
-------------------------------------------------------------------------------
Guarantees execution of cleanup scripts regardless of what happens inside your 
asynchronous error-handling loops.

* Syntax Architecture:
  try {
    // 1. Attempt dangerous action (Network communication, Data manipulation)
  } catch (err) {
    // 2. Fires ONLY if an exception occurs during the try block
  } finally {
    // 3. FIRES ALWAYS. Perfect for turning loaders/spinners off
  }

18. RETAINING DATA STATES (THE ARRAYS/OBJECTS SPREAD OPERATOR '...')
-------------------------------------------------------------------------------
When tracking user input events inside complex JavaScript objects, modifying one single 
input box field will naturally clear or erase all other sibling input properties if you do 
not explicitly copy them forward.

* The Wrong Pattern:
  onChange={(e) => setLoginForm({ email: e.target.value })} 
  // BUG: This removes the 'password' field entirely from state memory!

* The Correct Pattern (The Spread Rule):
  onChange={(e) => setLoginForm({ ...loginForm, email: e.target.value })}

* How it executes:
  1. The '...' operator reads your target object state layer and unpacks all existing 
     keys/values into a brand-new target object layout shell.
  2. The trailing parameters ('email: e.target.value') overwrite *only* that specific 
     key while keeping everything else perfectly intact.

21. THE NULLISH COALESCING OPERATOR ('??')
-------------------------------------------------------------------------------
An explicit fallback evaluation safety check designed specifically to replace 
unreliable OR ('||') falsy operators when managing database numeric zeros.

* The Syntax Rule:
  const solved = displayUser?.solvedProblems ?? 0;

* Structural Mechanics:
  1. If 'solvedProblems' evaluates strictly to 'null' or 'undefined', the operator 
     instantly steps in and returns the right-hand value (0).
  2. If 'solvedProblems' evaluates to an actual numeric 0, '??' accepts it as valid. 
     (Traditional '||' would incorrectly treat 0 as false and fallback anyway).

22. SEQUENTIAL PROMISE STACKING (THE '.THEN' ENGINE)
-------------------------------------------------------------------------------
An alternative approach to handling asynchronous code execution workflows without 
using 'async/await' try-catch statement structures.

* Code Execution Pattern:
  apiClient.getData()
    .then((result) => processResult(result))
    .catch((err) => handleErrors(err));

* Rule: Each '.then()' block passes its returned payload down as the processing 
  argument for the subsequent trailing '.then()' link block underneath it.
