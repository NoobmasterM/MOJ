===============================================================================
            THE 5-STEP BLUEPRINT FOR SCHEMA CHANGE MANAGEMENT
===============================================================================

If your platform ever expands to need structural database changes (e.g., adding 
a 'submitedLanguages' tracker or an admin-flag property), apply this cycle:

[STEP 1: BLUEPRINT EDITING]
Open 'server/prisma/schema.prisma'. Locate your target table block model container 
and add your new column field variable using valid Prisma definitions.

[STEP 2: TERMINAL COMPILER MIGRATION]
Head to your 'server/' directory terminal shell and execute the delta compiler command:
  npx prisma migrate dev --name add_new_column_field_flag

[STEP 3: CLIENT MODEL RE-GENERATION]
Prisma will automatically compile fresh system client code, but force-refresh your 
system text editors typescripts if warnings appear by explicitly typing:
  npx prisma generate

[STEP 4: BACKEND ROUTE ADJUSTMENTS]
Open your javascript routing managers situated inside 'server/routes/' (e.g., problems.js). 
Incorporate your newly added parameter variables inside your analytical queries.

[STEP 5: VISUAL SCREEN LAYOUT updates]
Open your frontend React workspace structures inside 'src/' (e.g., ProblemDetail.jsx). 
Map your new values into your loops to display them live over the internet browser canvas!
===============================================================================
