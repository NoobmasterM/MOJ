App.jsx: 
-------------------------------------------------------------------------------
1. REACT ROUTER DOM TAGS (DECONSTRUCTING APP.JSX)
-------------------------------------------------------------------------------
* <BrowserRouter>
  - What it is: The root routing wrapper component.
  - What it does: Activates HTML5 History API tracking. It allows your React web 
    app to manage URLs smoothly without triggering full browser page reloads.

* <Routes>
  - What it is: A structural wrapper component for route definitions.
  - What it does: It constantly listens to the current browser URL path and 
    scans through its children (<Route /> tags) to render only the single best 
    matching component layout.

* <Route>
  - What it is: A declarative URL matching definition component.
  - What it does: Maps a path to a React component view using two crucial props:
    1. 'path': The target web address structure (e.g., '/login').
    2. 'element': The specific component instance to render (e.g., <LoginRegister/>).

* Dynamic Route Segments (':id')
  - Example: path='/Problems/:id'
  - What it does: The ':' token turns 'id' into a dynamic variable placeholder. 
    If a user navigates to '/Problems/42', React Router matches this route, and 
    inside 'ProblemDetail.jsx' you can extract '42' using the 'useParams()' hook.

2. ASYNC FETCH DATA SYNTAX INSIDE USEEFFECT
-------------------------------------------------------------------------------
* The Rule: You cannot make the root callback function of a 'useEffect' hook 
  directly asynchronous (e.g., useEffect(async () => ...) is illegal syntax).

* The Workaround Pattern: You must declare an isolated async function inside the 
  hook, then execute it immediately underneath its block definition:
  
  useEffect(() => {
    const fetchContests = async () => {    // 1. Declare the wrapper function
      const data = await apiClient.getContests();
      setContests(data);
    };

    fetchContests();                       // 2. Execute the function immediately
  }, []);                                  // 3. Empty array means run once on boot

1. UNDERSTANDING THE STATISTICAL SCOREBOARD WIDGETS
-------------------------------------------------------------------------------
* The JS Map Deduplication Engine ('getUniqueContests'):
  - A developer might submit 20 solutions within a single competitive match.
  - Looping through raw submissions would create 20 duplicate entries on the UI.
  - The function passes values into 'new Map()'. It uses '.has()' and '.set()' 
    to guarantee that each Contest ID profile block prints exactly once.

* Array Pagination Cropping ('.slice(0, 8)'):
  - On the "Recent Activity" tab, the layout code caps row generation.
  - It crops the backend submission array down to only show items from index 0 
    up to (but not including) index 8, keeping the layout fast and readable.
